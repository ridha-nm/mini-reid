# Mini-Reid P1 and P2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the read-only digest into a persistent commitment ledger that tracks what Ridha owes, surfaces stalled work, and renders a forward-looking 7-day digest, then add model extraction for thread commitments and recurring cycles.

**Architecture:** A small Python package under `mini_reid/` with one module per responsibility: clients, sources, extract, ledger, render, cli. State is a committed `ledger.json`. P1 is rules only. P2 adds one model call behind a provider interface. No code in P1 sends anything.

**Tech Stack:** Python 3.11+ (stdlib only at runtime), pytest for tests, JSON for state, GitHub Actions for schedule.

**Spec:** `SPEC.md` in the repo root.

## Global Constraints

- Every timestamp is MYT, `Asia/Kuala_Lumpur` (UTC+8).
- Evidence quote is capped at 200 characters. Full message bodies are never stored.
- P1 makes no model calls and sends nothing to Slack or anywhere else.
- Client list is exactly the one in `SPEC.md`. Do not add clients from inference.
- Acknowledgement deny list: `Syaheedah`, `Max`.
- Ledger and digest live in a private repo. `.env` is never committed.
- Runtime dependencies: standard library only. Tests use pytest.

## Review Focus

Inputs the spec implies but no task's happy path covers. Each gets a test in its owning task.

1. A bot or automated Slack message that mentions Ridha must not become a commitment.
2. An unknown sender domain must land in the review bucket, never be silently dropped.
3. An ask with no date must appear with `due: null`, not be discarded for lacking one.
4. One draft edited many times is one row, aged from first creation, not one row per revision.
5. A message at 23:30 MYT must land in that day's digest even though the cron runs in UTC.

```python
from datetime import datetime, timedelta, timezone
from mini_reid.ledger import commitment_id, merge, apply_stalled

MYT = timezone(timedelta(hours=8))
NOW = datetime(2026, 10, 30, 9, 0, tzinfo=MYT)

def row(**kw):
    base = {"id": "x", "status": "open", "due": None, "kind": "mention",
            "created_at": "2026-10-29T09:00:00+08:00", "last_activity": "2026-10-29T09:00:00+08:00"}
    base.update(kw); return base

def test_id_ignores_case_and_punctuation():
    assert commitment_id("slack", "1", "Send the FSD.") == commitment_id("slack", "1", "send  the fsd")

def test_merge_is_idempotent():
    r = row(id="a")
    assert len(merge(merge([], [r]), [r])) == 1

def test_done_never_reopens():
    done = row(id="a", status="done")
    assert merge([done], [row(id="a", status="open")])[0]["status"] == "done"

def test_draft_older_than_one_day_is_stalled():
    out = apply_stalled([row(kind="draft", created_at="2026-10-29T08:00:00+08:00")], NOW)
    assert out[0]["status"] == "stalled"

def test_fresh_draft_is_not_stalled():
    out = apply_stalled([row(kind="draft", created_at="2026-10-29T10:00:00+08:00")], NOW)
    assert out[0]["status"] == "open"

def test_past_due_is_stalled():
    out = apply_stalled([row(due="2026-10-29")], NOW)
    assert out[0]["status"] == "stalled"
```

- [ ] **Step 3: Implement.** `normalize_what` lowercases, strips punctuation to single spaces, collapses whitespace. Id is `sha1(f"{source}|{native_id}|{normalize_what(what)}")`. `merge` keys on `id`, keeps existing terminal statuses (`done`, `dropped`) and never regresses them. `apply_stalled` sets `stalled` for the three SPEC triggers.
